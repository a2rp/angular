# RouterOutlet, RouterLink, and active route links: example

This example creates a small standalone Angular app with Home, Guides, About, and Not Found pages. It shows how configured routes, a shared navigation bar, a router outlet, and accessible active links work together.

The example uses the current standalone Angular style. Start with an Angular CLI application that already has Angular Router installed.

## File layout

~~~text
src/
├── app/
│   ├── pages/
│   │   ├── about-page.ts
│   │   ├── guides-page.ts
│   │   ├── home-page.ts
│   │   └── not-found-page.ts
│   ├── app.component.css
│   ├── app.component.html
│   ├── app.component.ts
│   ├── app.config.ts
│   └── app.routes.ts
└── main.ts
~~~

## 1. Define the routes

Create `src/app/app.routes.ts`. Each route maps a URL path to a page component. The wildcard route belongs last so specific paths have a chance to match first.

~~~ts
import {Routes} from '@angular/router';

import {AboutPage} from './pages/about-page';
import {GuidesPage} from './pages/guides-page';
import {HomePage} from './pages/home-page';
import {NotFoundPage} from './pages/not-found-page';

export const routes: Routes = [
  {
    path: '',
    component: HomePage,
    title: 'Home | Trail Notes',
  },
  {
    path: 'guides',
    component: GuidesPage,
    title: 'Guides | Trail Notes',
  },
  {
    path: 'about',
    component: AboutPage,
    title: 'About | Trail Notes',
  },
  {
    path: '**',
    component: NotFoundPage,
    title: 'Page not found | Trail Notes',
  },
];
~~~

The home path is the empty string because it represents the application root URL, `/`.

## 2. Register the router

In `src/app/app.config.ts`, register the route table with `provideRouter`. Keep other providers generated by the CLI and add this provider to the existing array if needed.

~~~ts
import {ApplicationConfig} from '@angular/core';
import {provideRouter} from '@angular/router';

import {routes} from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
  ],
};
~~~

The generated `src/main.ts` should bootstrap the root component with this configuration:

~~~ts
import {bootstrapApplication} from '@angular/platform-browser';

import {AppComponent} from './app/app.component';
import {appConfig} from './app/app.config';

bootstrapApplication(AppComponent, appConfig)
  .catch((error: unknown) => console.error(error));
~~~

## 3. Add the shared navigation and outlet

Create `src/app/app.component.ts` and import each router directive used by the component's templates:

~~~ts
import {Component} from '@angular/core';
import {
  RouterLink,
  RouterLinkActive,
  RouterOutlet,
} from '@angular/router';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterLink, RouterLinkActive, RouterOutlet],
  templateUrl: './app.component.html',
  styleUrl: './app.component.css',
})
export class AppComponent {}
~~~

Create `src/app/app.component.html`:

~~~html
<header class="site-header">
  <a class="brand" routerLink="/" aria-label="Trail Notes home">
    Trail Notes
  </a>

  <nav aria-label="Main navigation">
    <a
      routerLink="/"
      routerLinkActive="active"
      [routerLinkActiveOptions]="{exact: true}"
      ariaCurrentWhenActive="page"
    >
      Home
    </a>

    <a
      routerLink="/guides"
      routerLinkActive="active"
      ariaCurrentWhenActive="page"
    >
      Guides
    </a>

    <a
      routerLink="/about"
      routerLinkActive="active"
      ariaCurrentWhenActive="page"
    >
      About
    </a>
  </nav>
</header>

<main class="page-shell">
  <router-outlet />
</main>

<footer class="site-footer">
  <p>Practice routes, links, and accessible navigation.</p>
</footer>
~~~

The outlet is where the selected page component is displayed. The header, navigation, and footer are part of the shared root layout and remain in place as visitors move between routes.

The Home link uses exact matching. Without it, the root path can match more specific URLs and cause Home to appear active on other pages.

## 4. Create the routed page components

Each route component below is standalone and can be rendered directly by the router.

Create `src/app/pages/home-page.ts`:

~~~ts
import {Component} from '@angular/core';

@Component({
  selector: 'app-home-page',
  standalone: true,
  template: `
    <article>
      <h1>Welcome to Trail Notes</h1>
      <p>Use the navigation to explore the guide pages.</p>
      <p>This content is rendered inside the root router outlet.</p>
    </article>
  `,
})
export class HomePage {}
~~~

Create `src/app/pages/guides-page.ts`:

~~~ts
import {Component} from '@angular/core';

@Component({
  selector: 'app-guides-page',
  standalone: true,
  template: `
    <article>
      <h1>Guides</h1>
      <p>Browse practical notes for learning and building web apps.</p>
      <ul>
        <li>Plan a small feature before implementing it.</li>
        <li>Keep navigation labels clear and descriptive.</li>
        <li>Test keyboard access as you build.</li>
      </ul>
    </article>
  `,
})
export class GuidesPage {}
~~~

Create `src/app/pages/about-page.ts`:

~~~ts
import {Component} from '@angular/core';

@Component({
  selector: 'app-about-page',
  standalone: true,
  template: `
    <article>
      <h1>About Trail Notes</h1>
      <p>This page demonstrates a second route in the same application shell.</p>
    </article>
  `,
})
export class AboutPage {}
~~~

Create `src/app/pages/not-found-page.ts`. This page has its own link, so it imports `RouterLink`:

~~~ts
import {Component} from '@angular/core';
import {RouterLink} from '@angular/router';

@Component({
  selector: 'app-not-found-page',
  standalone: true,
  imports: [RouterLink],
  template: `
    <article>
      <h1>Page not found</h1>
      <p>The URL does not match a page in this example.</p>
      <a routerLink="/">Return to Home</a>
    </article>
  `,
})
export class NotFoundPage {}
~~~

The active style uses both weight and an underline rather than color alone. The template also sets `aria-current="page"` on the active navigation link, and the focus style remains visible for keyboard users.

## 6. Try the example

Start the development server:

~~~sh
ng serve
~~~

Open the local address shown by the CLI and check these behaviors:

1. The Home page appears at the application root.
2. Selecting Guides or About changes the URL and replaces the page content after the outlet.
3. The shared header and footer remain visible during navigation.
4. The active navigation link has the `active` class, underline, and `aria-current="page"`.
5. Home becomes active only at the exact root path.
6. Browser Back and Forward move between the routes.
7. A URL such as `/missing-page` displays the Not Found page.
8. Keyboard users can tab to links and see the focus outline.

## Troubleshooting

- **The page area stays blank:** confirm `RouterOutlet` is imported in `AppComponent` and its element is in the template.
- **The URL changes but the active class is missing:** verify that `RouterLinkActive` is imported, the link path matches a configured route, and the class name matches the stylesheet.
- **The Home link remains active on another page:** add `[routerLinkActiveOptions]="{exact: true}"` to the root link.
- **The router directive is reported as unknown:** add the directive to the `imports` of the standalone component whose template uses it.
- **The wrong page renders:** check the route paths and order, especially that the wildcard route is last.
