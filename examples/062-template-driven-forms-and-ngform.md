# Example: Build a template-driven contact form

This example builds a complete standalone Angular form with **FormsModule**, **ngForm**, **ngModel**, **ngModelGroup**, validation, accessible field messages, submission feedback, and a reset action.

The form has four fields arranged in two groups:

- **contact**: name and email
- **request**: topic and message

The group names also shape the aggregate value tracked by **NgForm**, so the form value mirrors the nested component model.

## 1. Create a practice application

Create a standalone Angular app:

~~~sh
ng new template-driven-form-demo --style=css
cd template-driven-form-demo
ng serve --open
~~~

Keep the generated application structure. Replace the contents of its root component TypeScript, template, and stylesheet files with the matching code below. Recent CLI versions may use names such as **app.ts** and **app.html** instead of **app.component.ts** and **app.component.html**; use the corresponding files already generated by your project.

## 2. Create the component model and submit handlers

Replace the root component TypeScript file:

~~~ts
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';
import type { NgForm } from '@angular/forms';

interface ContactRequest {
  contact: {
    fullName: string;
    email: string;
  };
  request: {
    topic: string;
    message: string;
  };
}

function createEmptyRequest(): ContactRequest {
  return {
    contact: {
      fullName: '',
      email: '',
    },
    request: {
      topic: '',
      message: '',
    },
  };
}

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [FormsModule],
  templateUrl: './app.component.html',
  styleUrl: './app.component.css',
})
export class AppComponent {
  model = createEmptyRequest();
  attemptedSubmit = false;
  savedSubmission: ContactRequest | null = null;

  submit(form: NgForm): void {
    this.attemptedSubmit = true;
    this.savedSubmission = null;

    if (form.invalid || form.pending) {
      form.control.markAllAsTouched();
      return;
    }

    // Copy nested objects so the preview is a submission snapshot.
    this.savedSubmission = {
      contact: { ...this.model.contact },
      request: { ...this.model.request },
    };
  }

  reset(form: NgForm): void {
    this.model = createEmptyRequest();
    this.attemptedSubmit = false;
    this.savedSubmission = null;
    form.resetForm(this.model);
  }
}
~~~

The application would usually pass the copied submission to an API service instead of storing it for display. The preview here makes it easy to see which values passed the form checks.

            }
          </p>

    <div class="form-status" aria-live="polite">
      @if (attemptedSubmit && requestForm.invalid) {
        <p class="error-summary">
          Some fields need your attention before the message can be sent.
        </p>
      }
    </div>

    <div class="actions">
      <button type="submit" [disabled]="requestForm.invalid || requestForm.pending">
        Send message
      </button>
      <button
        type="button"
        class="secondary"
        [disabled]="requestForm.pristine && !savedSubmission"
        (click)="reset(requestForm)"
      >
        Clear form
      </button>
    </div>
  </form>

  @if (savedSubmission; as submission) {
    <section class="success" aria-labelledby="success-title" role="status">
      <h2 id="success-title">Form is valid</h2>
      <p>This preview represents the data that could be sent to an API.</p>

      <dl>
        <dt>Name</dt>
        <dd>{{ submission.contact.fullName }}</dd>

        <dt>Email</dt>
        <dd>{{ submission.contact.email }}</dd>

        <dt>Topic</dt>
        <dd>{{ submission.request.topic }}</dd>

        <dt>Message</dt>
        <dd class="message-preview">{{ submission.request.message }}</dd>
      </dl>
    </section>
  }

  <details class="diagnostics">
    <summary>Inspect form state</summary>
    <p>
      Form valid: <strong>{{ requestForm.valid }}</strong>
    </p>
    <p>
      Form dirty: <strong>{{ requestForm.dirty }}</strong>
    </p>
    <p>
      Form touched: <strong>{{ requestForm.touched }}</strong>
    </p>
    <p>
      Registered contact name:
      <strong>{{ requestForm.value.contact?.fullName || 'not entered' }}</strong>
    </p>
    <p>
      Registered topic:
      <strong>{{ requestForm.value.request?.topic || 'not selected' }}</strong>
    </p>
  </details>

Each **ngModel** control inside the form has a name, so Angular can register it. The two **ngModelGroup** directives make the aggregate form value nested under **contact** and **request**, matching the component model shape.

The form uses **novalidate** so the browser does not show a second set of popup messages. Angular still evaluates the validators, and the template displays custom feedback.

## 5. Try the form

1. Submit the empty form. The button should be disabled, and the form state panel should report that it is invalid.
2. Enter a one-character name, then move focus away. The minimum-length message should appear.
3. Enter an invalid email address and select a topic.
4. Enter a message shorter than 20 characters. Its minimum-length message should appear after blur.
5. Complete all fields correctly. The send button becomes available.
6. Submit the form. The valid-data preview appears below the form.
7. Choose **Clear form**. Values, validation state, and the preview should reset.

## Understand the aggregate form value

The form reference points to **NgForm**, so its value contains only registered controls. Because the inputs are inside two named groups, the aggregate value is shaped like this:

~~~json
{
  "contact": {
    "fullName": "Asha Rao",
    "email": "asha@example.com"
  },
  "request": {
    "topic": "technical",
    "message": "I need help updating my account settings."
  }
}
~~~

The component model uses the same shape. **[(ngModel)]** updates its fields, while **NgForm** maintains the registered control tree and validation state. The submit handler checks that state before copying values into the preview.

## Why the example uses both a disabled button and a submit guard

The disabled button communicates that required fields are incomplete. The component still checks **form.invalid** and **form.pending** inside the submit method. UI state alone should not decide whether application data may be processed.

The submit handler also marks controls touched after an invalid submission. This reveals the field feedback and helps users locate the fields that need attention.

## Accessibility details

- Every control has a visible label associated through **for** and **id**.
- Help and error text are referenced with **aria-describedby**.
- Invalid fields expose **aria-invalid** only after their errors are relevant.
- Error text explains how to correct a problem; the border color is supplemental.
- The result preview uses a live status region so the successful state is announced.

## Further practice

- Add a phone field with a pattern and a clear explanation of the accepted format.
- Add a checkbox for consent and require it before submission.
- Add an optional local search control with **[ngModelOptions]="{ standalone: true }"** and confirm that it does not appear in the form value.
- Change the nested groups and component model together, then inspect the aggregate value.
- Replace the preview assignment with an injected service that sends the valid request to a server.
- Add server-side validation and display a server rejection without treating client validation as authoritative.
